# XP+ v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Evolve XP `2.0.0-rc18.3` into backward-compatible XP+ `2.1.x` without forcing migration of existing XP projects, while adding safe engine upgrades, canonical AI/spec schemas, project readiness auditing, compact/deep bundles, and universal compatibility gates.

**Architecture:** Keep the existing XP engine and compatibility surfaces (`xp`, `.xp/`, profile/state/package protocol v1) intact. Add focused modules for schema authority, project doctor, bundle generation, engine lifecycle, and compatibility fixtures; integrate them through the existing CLI/autopilot boundaries rather than rewriting core state, package, recovery, or checkpoint logic.

**Tech Stack:** Python 3 standard library, Git, Node/npm adapters, PostgreSQL/psql adapter, Termux/X11 primary platform.

**Spec:** `docs/superpowers/specs/2026-09-13-xp-plus-v1-design.md` (source content: `XP_PLUS_BLUEPRINT_v1.0_FINAL_LOCK.md`)

## Global Constraints

- Product display name is `XP+`; CLI remains `xp`.
- Internal engine version uses normal semver, target first stable line `2.1.x`.
- `.xp/`, `XP_PKG_*`, existing registry identity, control repo, checkpoints, and work branches remain valid.
- `profile_version: 1`, `state_version: 1`, and `protocol_version: 1` remain natively supported.
- No forced migration of existing projects.
- Existing Segeran Jiwa POS Legacy and Next projects must remain usable.
- No production deployment automation is added in XP+ v1.
- No business-specific Segeran Jiwa logic is added to XP.
- Engine development happens in an isolated development branch/worktree, never by editing `~/.expert-workstation/versions/*`.
- Do not directly develop on the stable `xp-engine` branch; promote through reviewed Git history at the final release gate.
- Every functional change is test-first.
- A failed engine candidate must not mutate project source.
- Stable GitHub release is forbidden until universal, Legacy, Next, clean-install, and upgrade/rollback gates pass.

```text
XP+-00 compatibility freeze
    ↓
XP+-01 safe engine upgrade
    ↓
XP+-02 canonical schema
    ↓
XP+-03 project doctor/onboarding
    ↓
XP+-04 bundle v2
    ↓
XP+-05 adapter hardening
    ↓
XP+-06 compatibility readers
    ↓
XP+-07 universal + real-project acceptance
    ↓
XP+-08 RC
    ↓
XP+-09 stable
    ↓
XP+-10 GitHub release sync
```

Stop immediately and audit before continuing if:

- a profile v1 fixture stops loading,
- a state v1 fixture stops loading,
- protocol-v1 package validation changes unexpectedly,
- existing Next checkpoint/run becomes unreadable,
- Legacy/Next source is mutated by a compatibility smoke,
- an engine candidate changes `active-version` before validation,
- failed activation cannot restore `previous-version`,
- schema output and pkg-build behavior disagree.
